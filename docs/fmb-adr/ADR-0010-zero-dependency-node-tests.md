# ADR-0010：測試是零依賴的 Node 腳本，同時扮演規格書

- 狀態：已採行
- 相關檔案：`tests/test_zizai.js`、`tests/RESULT_1151001*.txt`、`README.md`

## 背景

專案沒有 CI、沒有 npm、也不打算引入測試框架（ADR-0001）。但資料正確性必須「與來源逐課比對」，UI 元件（注音、考卷、讀音修改）也需要可驗證。歷史上有整批資料是編造的前例（ADR-0004），所以測試的價值遠高於一般專案。

## 決策

1. 測試是一支以 Node 22 執行的單檔腳本 `tests/test_zizai.js`，**只用 Node 內建模組**，不需 `npm install`。
2. 以「模組 1～N」編號組織，涵蓋：週次與進度邏輯、出題與考卷、各年級資料合規、與 CSV 快照逐課比對、注音/部首/筆畫不得為空、讀音重算（含聲調）與語詞一致性、破音門檻、注音格式驗證、儲存/還原、語詞替換、用注音元件實際繪製字卡與考卷、回報 payload 對照 worker 規則、來源白名單、各種失敗降級、localStorage 不可用、匯出格式、以及「下拉選單項目數等於實際單元數」「沒有例句時不得有空大題」等畫面規則。
3. **缺外部大檔時標示「略過」**：沒有辭典檔時 4 項略過、沒有 CSV 快照時 16 項略過、沒有開發分支歷史時 1 項略過；略過不算通過也不算失敗。
4. 每輪實際輸出留在 `tests/RESULT_1151001*.txt`，作為驗收證據。
5. 對關鍵純邏輯（`src/readings.js` 的門檻、語詞替換保護、白名單、注音驗證）做**變異測試**：故意改壞規則時測試必須失敗，以證明測試有效。
6. 測試不得連線到網路上的正式服務；需要憑證或識別值時使用明顯假字串；檔案讀寫限於 repo 內或系統暫存目錄。

## 取捨

**換到**

-  clone 後一條指令就能驗證，沒有環境安裝成本。
- 測試即規格：資料格式、UI 規則、回報 payload 的預期都寫在測試裡。
- 略過機制讓缺少授權資料的環境仍可執行大部分測試。

**付出**

- 沒有 coverage 工具、沒有 watch mode、斷言都要自己寫。
- 通過數會隨環境變動（66 通過 / 21 略過 ↔ 87 全過），只看「通過數」會誤判。
- 單檔測試愈長愈難維護，模組編號與命名必須持續保持一致。

## 後果

- 驗收時必須同時看**通過、略過、失敗**三個數字與總數，不能只說「全數通過」。
- 新增資料、年級或欄位時要同步新增比對項目；文件（`README.md`、`DONE_1151001.md`）提到的項數也要更新。
- 不得把略過改成靜默通過，也不得為了通過而放寬比對條件。
- 若引入需安裝的測試框架，必須先開新 ADR 並說明與 ADR-0001 的衝突如何處理。
