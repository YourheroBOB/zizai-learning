# zizai-learning 語言版本、相依套件與執行環境升級計畫

> 本文件僅記錄盤點與升級提案；本次未安裝套件、未升級語言或工具，也未修改既有程式與資料。  
> 盤點基準為提供的 repository 檔案內容，未連線查閱即時版本或安全公告。

## 1. 現況盤點

### 1.1 語言與格式版本

| 項目 | 現況 | 評估 |
|---|---|---|
| HTML | HTML5，`<!DOCTYPE html>`、`lang="zh-Hant-TW"` | 無編譯或轉譯層，不需語言升級 |
| CSS | 原生 CSS，使用 CSS variables、Grid、Flexbox、`clamp()`、`dvh` 等現代功能 | 未宣告最低瀏覽器版本；應先定義支援矩陣 |
| 瀏覽器 JavaScript | 原生 classic script，使用 Fetch、DOM、`localStorage`、Promise、`async/await` | 無 Babel、TypeScript 或 polyfill 鏈；不宜為升級而增加前端框架 |
| Node.js | README 明確指定 Node.js 22 | 唯一明確的 runtime 版本，但 repo 內沒有 `.node-version` 或 `engines` 可鎖定 |
| Python | 文件僅寫 `python3` | 沒有最低版本；是主要可重現性缺口 |
| JSON Schema | `data/schema.json` 使用 Draft 2020-12 | 版本本身可保留；目前未明確描述後來使用的 `readings`、`ambiguous` 欄位 |
| Python／Node 工具模組格式 | Python 為一般腳本；PDF 工具使用 `.mjs` | 工具與瀏覽器程式邊界清楚，升級時應分開處理 |

### 1.2 相依套件

- 沒有 `package.json`、npm lockfile、`requirements.txt`、`pyproject.toml` 或 pip lockfile。
- 沒有可辨識的第三方 npm／PyPI runtime 或 development dependency。
- 測試是 `tests/test_zizai.js` 的自製測試器；打包是 `tools/bundle.py` 的自製打包流程。
- Python 工具目前使用標準函式庫；PDF 工具使用 Node.js 內建模組與本機 Chrome DevTools Protocol。
- 因此目前沒有一般套件版本落後問題；主要風險是缺少 runtime、瀏覽器及外部資料的固定基準。

### 1.3 執行環境

| 環境 | 用途 | 現行要求／風險 |
|---|---|---|
| 現代瀏覽器 | 網頁版、localStorage、列印 | 最低版本未定義 |
| Python 3 | 資料重建與打包 | 最低版本未定義 |
| Node.js 22 | 測試與 PDF 產生 | 有文件要求但無檔案鎖定 |
| Chrome／Chromium | 無頭 PDF 與列印行為 | 未固定版本 |
| 本機 HTTP server | 測試 JSON 載入 | 應只綁 `127.0.0.1` |
| GitHub Pages 類靜態環境 | 網頁版發布 | 依賴相對路徑 JSON；無後端需求 |

### 1.4 外部輸入與非套件相依

- 網頁版使用 Google Fonts；打包離線版移除該外部字型。
- 教材重建依賴外部 CSV 與辭典壓縮檔；來源會變動，目前主要靠下載時間辨識，未見固定校驗碼。
- 使用者點擊後會開啟教育部網站；這不是自動測試依賴。
- 讀音回報使用同源 `/api/report`；後端契約與版本不在本 repo。

## 2. 風險評估

| 等級 | 風險 | 影響 | 保守處理 |
|---|---|---|---|
| 高 | Python 版本未定義 | 不同主機可能有編碼、JSON、正規表示式或路徑差異 | 先確立 Python 3.11 下限並平行驗證 3.12 |
| 高 | Node.js 22 僅存在於文件 | 環境漂移，測試結果不可重現 | 以 `.node-version` 或 `engines` 固定，再測試 Node.js 24 |
| 高 | 教材與辭典來源會更新 | 重建資料可能無聲改變課次、字數、讀音或占比 | 記錄來源版本與 SHA-256；來源更新與程式升級分批進行 |
| 高 | 教材來源授權條款未載明 | 可能限制散布或發布 | 發布前由 BOB／法務確認，不推定為可自由散布 |
| 中高 | 未見 CI 設定 | 升級回歸可能只在人工測試後才發現 | 先準備 CI 草稿，但工作流程需另案核准 |
| 中高 | Schema 未完整描述新欄位 | 驗證器可能漏驗或錯誤接受資料 | 補成版本化 schema，不破壞既有欄位 |
| 中 | Chrome 版本未固定 | PDF、列印媒體與字型度量可能不同 | 記錄 PDF 工具使用版本並建立前一主要版對照 |
| 中 | 遠端字型有可用性、隱私及延遲風險 | 載入失敗時雖有 fallback，版面仍可能不同 | 保留 fallback；是否改本機字型另行評估授權與體積 |
| 中 | 無套件清單、SBOM 或鎖檔 | 未來新增套件時無法重建與稽核 | 新增任何套件前先做必要性審查，並精確鎖版 |
| 中 | 回報 API 不在本 repo | 後端欄位變更可能造成回報失敗 | 以本機假端點驗證前後端契約，不呼叫正式服務 |

> 因無第三方套件版本清單，且本次未進行即時弱點資料庫查詢，不能宣稱特定 CVE 狀態。正式升級時應以實際鎖檔與 runtime 版本重新產出 SBOM／掃描結果。

## 3. 必須維持的相容性契約

1. 教材 JSON 的既有欄位、單元順序與讀音占比格式。
2. `localStorage` 舊資料可遷移，既有進度與讀音修改不得遺失。
3. 讀音修改匯出格式及 `/api/report` payload 維持相容。
4. 打包檔仍可在 `file://` 離線開啟，且只有使用者主動勾選回報時才可能發出同源請求。
5. A4 學生卷、答案卷、注音位置及頁數不得回歸。
6. 缺少教材／辭典來源時，資料重建必須安全停止，且不得改寫 `data/`。
7. 測試略過項目必須明確標示為略過，不能冒充通過。

## 4. 分階段升級計畫

### 階段 0：建立可重現基準

- **變更：**記錄 Node、Python、Chrome、OS、Git 版本；保存目前測試結果、資料校驗碼與打包產物校驗碼。
- **相容性風險：**低；不同工作站可能產生不同基準，應記錄差異而非先強制統一。
- **驗證方式：**執行現有測試；以暫存目錄打包；缺來源時確認資料零差異。
- **回滾方式：**僅移除基準文件即可，不影響 runtime 或使用者資料。

### 階段 1：補齊契約與測試基準

- **變更：**明確描述 `readings`、`ambiguous`、歷史版／體驗版資料差異；保存 localStorage 遷移與 API payload 契約。
- **相容性風險：**收緊 schema 可能使既有資料失敗；改欄位名稱可能破壞舊資料。
- **驗證方式：**所有既有 JSON 通過新舊 schema 相容矩陣；舊 localStorage 可匯入、遷移及再匯出；API 僅用本機假端點。
- **回滾方式：**保留舊 schema 一個相容週期；新 schema 失敗時改讀舊格式，不刪除舊資料。

### 階段 2：確立 Python 支援範圍

- **變更：**先以 Python 3.11 為暫定下限，平行驗證 3.12；確認後再加入版本鎖定。
- **相容性風險：**JSON 序列化、正規表示式、編碼及路徑行為可能有版本差異。
- **驗證方式：**兩版本執行語法檢查、測試及暫存目錄資料重建；比較 JSON 結構與校驗碼。
- **回滾方式：**維持上一個已驗證 Python 版本；資料異常時還原資料提交，不混改教材內容。

### 階段 3：Node.js 22 → 24 評估

- **變更：**Node.js 22 暫留最低基準；新增 Node.js 24 並行測試，確認官方支援狀態後才決定是否提高下限。
- **相容性風險：**HTTP、WebSocket、child process、ESM 或錯誤事件行為可能改變；Chrome CDP 行為亦可能受影響。
- **驗證方式：**22、24 各跑完整測試、暫存打包與 PDF 產生；檢查 PDF 頁數、大小及列印外觀。
- **回滾方式：**將版本 pin 還原為 22；只重建受影響產物，不還原無關資料變更。

### 階段 4：相依套件治理

- **變更：**維持零第三方 runtime 套件。只有標準函式庫確實不足時才新增 development dependency，並提交 manifest、精確版本與 lockfile。
- **相容性風險：**新套件可能帶入原生模組、postinstall、runtime 下限或供應鏈風險。
- **驗證方式：**從乾淨環境以 lockfile 重建；確認打包產物未帶入依賴；產生 SBOM／授權清單。
- **回滾方式：**移除新增 manifest 與 lockfile，回復零依賴工具鏈。

### 階段 5：瀏覽器與 Chrome 支援矩陣

- **變更：**由 BOB 決定是否支援 Chrome、Edge、Firefox、Safari 的最新兩個穩定版；記錄 PDF 工具的 Chrome 版本。
- **相容性風險：**不同瀏覽器的列印分頁、字型度量、Fetch 與 localStorage 行為不同。
- **驗證方式：**驗證 320／375 寬度、鍵盤操作、深淺色、線上練習、讀音修改、學生卷、答案卷及離線開啟；回報仍只用本機假端點。
- **回滾方式：**回復上一版瀏覽器基準；CSS／字型問題獨立回退，不牽動資料格式。

### 階段 6：外部資料版本化

- **變更：**為教材與辭典來源記錄來源版本、取得時間、SHA-256、產生工具版本及授權狀態；原則上不提交未授權的來源內容。
- **相容性風險：**上游更新可能改變課次、生字、讀音、占比與破音集合，即使程式未變。
- **驗證方式：**每次只更新一個來源，在暫存目錄重建並輸出結構化差異；確認單元數、主讀音、占比及 `ambiguous` 集合。
- **回滾方式：**使用上一個已知良好來源校驗碼重建，或獨立還原資料提交；不得從已漂移來源直接重跑。

### 階段 7：發布與回滾演練

- **變更：**每階段採獨立提交；發布前保存前一版產物及資料校驗碼。CI 或 secrets 設定不在本次變更範圍，須另案核准。
- **相容性風險：**多批變更同時上線會延誤定位；前端與資料版本不同步可能造成讀取錯誤。
- **驗證方式：**候選產物執行測試、打包、瀏覽器 smoke test、列印預覽與校驗碼核對；在隔離環境演練回復上一版。
- **回滾方式：**程式問題回復上一版靜態產物；資料問題回復上一個核准資料提交；工具問題回復版本 pin。

## 5. 建議驗證命令

以下命令只使用本機資源；打包與 PDF 輸出應放在暫存目錄：

```bash
node --version
python3 --version
node tests/test_zizai.js

tmp_dir="$(mktemp -d)"
ZIZAI_OUT="$tmp_dir/bundle" python3 tools/bundle.py
node tools/make_sample_pdfs.mjs --out "$tmp_dir/pdf"
```

README 記載的既有基準：

- 補齊字典、教材快照及歷史資料時：87 項全過。
- 一般 bare clone：預期 66 項通過、21 項略過、0 項失敗。
- 略過不算通過；升級報告必須分開列出通過、失敗與略過。

本次只有 Markdown 文件變更，因此沒有適用產品測試；既有測試結果為 repository 先前紀錄，非本次重新執行結果。

## 6. 決策點

### 本次保守決策

- 不實際升級、不新增 runtime 套件、不修改既有檔案。
- Node.js 22 暫留；Python 暫定 3.11 下限並驗證 3.12。
- JSON Schema 暫留 Draft 2020-12，先補契約而非更換草案。
- 測試只用本機檔案、loopback 與假端點，不呼叫正式服務。
- 未確認授權前，不提交教材來源內容，也不視為已取得散布權利。

### 需要 BOB 決策

1. 是否核准 Python 3.11 下限及 Node.js 24 升級時程。
2. 瀏覽器與 Chrome 支援矩陣。
3. 是否維持零第三方套件，或允許新增精確鎖定的 development dependency。
4. 是否另案核准 CI 工作流程變更。
5. 程式碼授權、教材散布權利及外部來源保留政策。
6. 是否將 Google Fonts 改為本機字型。
7. `/api/report` 正式契約與維護責任。
8. 歷史版與體驗版是否建立獨立 schema。
9. 發布、觀察期及回滾決策負責人。
