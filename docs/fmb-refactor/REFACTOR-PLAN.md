# zizai-learning 分批重構計畫

## 目的與界線

本計畫以小批次整理前端主程式、讀音功能與本機工具，讓每批變更都能獨立驗證，並維持既有網頁版、`file://` 單檔版、教材資料格式與使用者操作行為。

依目前可見的檔案內容，`src/app.js`、`src/readings.js`、`tests/test_zizai.js` 等完整內容未提供。因此，下列涉及這些檔案的觀察是**重構候選與待確認項目**，不代表已完成逐函式檢視；實作前應先以完整原始碼確認實際責任、依賴與測試覆蓋。

**不在計畫範圍內：**

- 不變更教材資料、資料 schema、使用者儲存格式或回報協定。
- 不合併用途不同的教材建置流程：二年級等資料與一、三至六年級資料有不同來源與輸入條件。
- 不改變回報的使用者同意條件、來源限制或失敗降級行為。
- 不在重構中順手改版 UI、引入套件或改用需要建置步驟的模組載入方式。

## 目標結構（提案）

先維持現有頁面入口、傳統 script 載入方式與工具命令，不要求引入套件或建置系統。只有在確認現有全域介面後，才決定各模組的實際匯出方式。

```text
src/
  app.js                         # 組裝頁面功能、啟動與跨功能協調
  modules/
    curriculum.js                # 年級、教材類型與資料載入
    progress.js                  # 進度狀態與進度呈現
    quiz.js                      # 線上練習
    worksheet.js                 # 考卷出題、呈現與列印接線
    reading-core.js              # 讀音格式、正規化與純判定
    reading-storage.js           # localStorage 讀寫
    reading-report.js            # 使用者勾選後的回報傳輸
  readings.js                    # 過渡期相容入口；確認無呼叫端後再評估移除
  zhuyin.js                      # 保留注音字格公開介面

tools/
  bundle.py                      # CLI：讀檔、輸出與錯誤呈現
  bundle_core.py                 # 純轉換及打包檢查
  make_sample_pdfs.mjs           # PDF 工具 CLI 與資源生命週期
  pdf/                           # 僅在抽出的輔助模組已能獨立測試時再建立
```

上述模組名稱是目標分工，不要求一次建立全部檔案。若新增前端 script，需同步檢查 `index.html` 的載入順序與 `tools/bundle.py` 的腳本順序斷言；單檔版仍須可離線開啟。

## 分批計畫

### 第 0 批：固定基線與行為契約

**步驟**

1. 以完整原始碼盤點 `app.js`、`readings.js`、兩個測試檔及工具入口，記錄模組公開函式、全域狀態、DOM 依賴、儲存及網路副作用。
2. 把主要使用情境列成檢核表：年級與教材切換、進度覆寫、互動出題、考卷與答案卷、讀音修改／還原／匯出，以及回報勾選與未勾選。
3. 記錄基線測試輸出，明確標出因來源檔缺少而略過的項目，不將略過計入通過。

**先補的測試**

- 為目前缺少獨立覆蓋的功能增加最小行為測試；不先做程式搬移。
- 測試資料只使用固定、虛構的教材與讀音；需要假值時使用明顯假字串。
- 不以真實端點作測試目標；回報傳輸使用注入的 stub。

**獨立驗證**

- 執行 `node tests/test_zizai.js`，並將通過、失敗、略過分開記錄。
- 執行 `node tests/test_fmb_zhuyin.test.mjs`。
- 測試只使用 repo 內既有資料或受控 fixture，不下載外部資料。

**風險**

- 現有測試可能依賴本機來源快照；需區分環境缺件與程式問題。
- 不因建立基線而複製受授權限制的來源資料或使用者內容。

### 第 1 批：抽離打包純轉換

**目標**

讓 `tools/bundle.py` 只負責 CLI 與檔案輸入輸出；HTML／CSS／JavaScript 的組裝和殘留檢查可在不寫檔的情況下測試。

**步驟**

1. 將打包內容改為接受明確輸入並回傳產物的函式。
2. 將教材 JSON 載入、輸出檔案寫入及 CLI 執行放進明確入口；避免匯入模組時建立輸出目錄或執行打包。
3. 保留現有資源順序、替換命中次數、網路面限制與外部資源檢查。
4. `ZIZAI_OUT` 等輸出位置在測試中指向臨時目錄；不以執行打包來覆寫其他檔案。

**先補的測試**

- 純轉換測試：輸入最小 fixture，檢查資源內嵌、CSS／JS 順序與必要資料區塊。
- 負向測試：替換標記缺漏或不唯一、腳本順序不符、禁止的網路呼叫出現時應明確失敗。
- 副作用測試：匯入 `bundle.py` 不應建立資料夾或寫檔。

**獨立驗證**

- 執行 Python 語法檢查及新增的打包測試。
- 用臨時輸出目錄執行打包，確認產物可產生且兩份 HTML 相同；不連線正式服務。
- 執行既有 Node 測試，確認前端與資料行為未改變。

**風險**

- 若抽函式時放寬既有斷言，可能使打包不再及早拒絕不相容輸入。
- 完整教材 JSON 很大；測試宜以 fixture 驗證純邏輯，另以本機完整資料做整合驗收。

### 第 2 批：拆分 `app.js` 的功能責任

**目標**

讓 `app.js` 組裝功能與管理啟動流程，不再同時承擔所有畫面的狀態轉換、DOM 渲染及事件行為。

**步驟**

1. 先依實際原始碼確認函式與狀態所有權，不依架構文件推測函式名稱。
2. 優先拆出教材選擇與載入，再拆進度、互動練習、考卷；每次只遷移一個責任。
3. 新模組先接受明確依賴（教材資料、必要 DOM 節點、既有服務），避免引入新的隱式全域狀態。
4. 保留舊呼叫介面作為薄轉接層，待呼叫端與測試確認後才移除。
5. 每批新增 script 時同步更新網頁載入順序與打包器預期順序，並確認離線打包路徑不使用 `fetch` 讀外部教材檔。

**先補的測試**

- 年級／教材切換後，資料檔與版本狀態一致；110 與 demo 對年級的限制維持不變。
- 進度自動推算、手動覆寫及切換教材後的狀態更新。
- 練習與考卷使用相同的出題範圍邊界；無例句時仍不產生空白大題。
- 測試以固定時間、固定隨機來源或可注入替身避免結果不穩定。

**獨立驗證**

- 每遷移一個功能即執行對應行為測試與 `node tests/test_zizai.js`。
- 驗證網頁版資料載入及單檔離線版資料載入各走原有路徑。
- 以瀏覽器手動檢查分頁切換、練習及考卷，不把新增外部服務作為驗收條件。

**風險**

- 狀態若在多個畫面間共享，過早拆檔可能造成初始化順序錯誤或畫面不一致。
- 單檔打包器明確檢查 script 順序；前端拆分必須與打包器同批驗證。
- 不應趁拆分修改 localStorage key、資料 schema 或使用者操作語意。

### 第 3 批：分離讀音純邏輯、儲存與回報

**目標**

把讀音規則與瀏覽器／網路 I/O 的責任界線明確化，讓純邏輯可在 Node 測試，I/O 可注入替身驗證。

**步驟**

1. 盤點 `readings.js` 的公開 API，將注音驗證、正規化、候選判定等純邏輯列為穩定核心。
2. 將 localStorage 存取整理為儲存介面；保留既有鍵名、資料格式與錯誤降級。
3. 將回報請求集中於單一介面；維持只有使用者勾選才傳送、既有來源條件與失敗訊息。
4. 將匯出格式與 UI 操作分開；由 `app.js` 或畫面模組負責接線，不讓純核心操作 DOM。
5. 若需拆新檔，維持 `readings.js` 相容入口，直到既有呼叫端、測試及打包器均改接完成。

**先補的測試**

- 注音合法／不合法格式、輕聲正規化與儲存資料損毀。
- localStorage 不可用、讀取失敗、寫入失敗及還原行為。
- 匯出文字／JSON 的欄位與內容格式。
- 未勾選不傳送；勾選時檢查 payload；網路錯誤、逾時與非成功回應仍保留本機資料並降級。
- 測試使用 stub，不呼叫真實回報端點，也不把使用者備註或訊息內容寫入測試輸出。

**獨立驗證**

- 執行 `node tests/test_zizai.js` 與 `node tests/test_fmb_zhuyin.test.mjs`。
- 執行打包並檢查內嵌腳本只保留既有允許的回報請求路徑。
- 手動確認字卡、彈窗、練習及考卷仍使用修改後讀音。

**風險**

- 本機儲存格式包含供匯出與語詞替換使用的既有欄位；精簡格式可能破壞舊資料相容性。
- 回報條件或 payload 的細微變更可能影響整合站端點；本批只移動責任，不調整協定。
- UI、純邏輯和儲存若同時改動，失敗原因會難以定位，應分小次提交。

### 第 4 批：整理 PDF 工具的協調流程

**目標**

縮短 PDF 工具入口的控制流程，讓等待頁面與列印流程可由替身測試；Chrome 與本機伺服器仍只由入口統一清理。

**步驟**

1. 將「等待考卷渲染完成」整理成獨立步驟，明確保留逾時與頁面錯誤處理。
2. 將「取得題目摘要」及「輸出兩種 PDF」整理成小函式，確保兩份 PDF 使用同一份 DOM。
3. 將本機伺服器根目錄與輸出目錄設為明確依賴，便於測試只使用臨時 fixture。
4. 保留只啟動及清理本工具所建立之 Chrome、伺服器與臨時資料的生命週期。
5. 本批不修改路徑安全政策或擴大伺服器可服務的檔案範圍；若發現安全問題，另列獨立修正與驗收。

**先補的測試**

- 頁面未就緒時可在逾時後清理資源。
- 列印失敗時仍會執行清理。
- 學生卷與答案卷輸出共用同一頁面狀態。
- 伺服器 fixture 與輸出皆位於測試臨時目錄；僅使用 loopback，不連線外部服務。
- 不要求每次測試都啟動 Chrome；必要時以注入的 CDP／列印替身驗證協調邏輯。

**獨立驗證**

- 執行新增 Node 測試及語法檢查。
- 有本機 Chrome 時再做手動整合驗證；沒有 Chrome 時標示為未執行，不將其視為通過。
- 不為重構計畫或一般測試重新產生 repo 中的 PDF 成品。

**風險**

- 過度拆分 CDP 呼叫可能使非同步錯誤與資源清理順序更難追蹤。
- 無頭瀏覽器結果可能受平台與字型差異影響；應將核心邏輯測試與視覺驗收分開。

### 第 5 批：命名整理與收尾

**目標**

建立一致且漸進的內部命名方式，不破壞既有資料鍵、CSS 整合介面或公開入口。

**步驟**

1. 建立術語表，明確區分年級 `grade`、教材類型／學期、出版社 `publisher`、課次 `lessonNo` 與顯示標題 `title`。
2. 為 `bopomofo`（整串顯示）與 `bopomofoArray`（逐字陣列）補上明確的程式內文件或轉接函式，不先改資料欄位。
3. 記錄 `tp-`、`tpz-`、`zz-` 的既有用途及適用範圍；新增命名依專案實際整合規則決定，避免一次性重命名所有 class。
4. 對二年級既有檔名、`TPZhuyin` 及其他公開名稱保留相容，除非另有獨立的版本決策。

**先補的測試**

- 搜尋並盤點外部依賴的名稱，包括 HTML、CSS、測試、打包腳本與文件。
- 若有內部函式改名，新增對應測試或保留轉接函式；確認資料 JSON 不被改寫。
- 執行完整既有測試與打包驗證。

**風險**

- CSS class、資料欄位與 script 全域名稱可能已被整合站使用；只看本 repo 無法證明可安全移除。
- 統一命名本身不應凌駕相容性或可維護性；若名稱差異是有意區隔，保留並記錄即可。

### PDF 工具：等待與列印協調流程分離

目前 `main()` 直接執行導覽並輪詢頁面是否完成：

```js
await call('Page.enable');
await call('Page.navigate', { url: pageUrl });

const t0 = Date.now();
for (;;) {
  const ready = await evaluate(
    `document.querySelectorAll('#sheet-items > *').length > 0 && document.querySelectorAll('#answer-items > *').length > 0 && document.querySelectorAll('#sheet-words > *').length > 0`,
  ).catch(() => false);
  if (ready) break;
  if (Date.now() - t0 > 20000) throw new Error('逾時：考卷沒有渲染出題目');
  await sleep(200);
}
```

目標是讓入口呈現生命週期，細節交由可注入依賴的小函式處理：

```js
async function renderWorksheetPage({ call, evaluate, pageUrl }) {
  await call('Page.enable');
  await call('Page.navigate', { url: pageUrl });
  await waitForWorksheet({ evaluate, sleep });
}

async function printWorksheetVariants({ evaluate, printTo }) {
  await printTo('sample-worksheet-with-answers.pdf');
  await hideAnswerSheet(evaluate);
  await printTo('sample-worksheet.pdf');
}

// main() 保留伺服器、Chrome、CDP 的啟動與 finally 清理。
```

驗收重點：兩份輸出仍由同一份 DOM 產生；逾時或失敗時入口仍能清理資源。
