# 個人資料類別、資料流、保存與記錄檔風險

## 證據與限制

本文件依 `README.md`、`docs/fmb/ARCHITECTURE.md`、`docs/fmb-runbook/README.md`、`DONE_1151001.md` 及本次提供的程式片段整理。下表區分「文件記載」與「尚未由完整程式碼／部署端確認」。本專案沒有帳號或後端資料庫的描述，不代表外部部署服務完全不處理資料。

本表不列入任何真實使用者、訊息或案件資料。

## 可辨識的個人資料類別

| 資料類別 | 可能欄位／內容 | 來源與用途 | 儲存／流向 | 風險與確認事項 |
|---|---|---|---|---|
| 學習進度與偏好 | 文件提及學習進度、手動指定進度及本機狀態；完整欄位與 localStorage key 未在可見內容中完整列明 | 使用者操作；供本機顯示進度與學習狀態 | 專案文件稱儲存在使用者瀏覽器 localStorage | 若與姓名、裝置或家庭帳號等資訊結合，可能形成可識別學生的學習紀錄。需由完整 `app.js` 確認欄位、key、清除入口與是否另有傳輸。 |
| 精熟／待加強狀態 | 生字的已精熟或待加強狀態；具體儲存格式未確認 | 使用者操作；呈現進度或複習範圍 | 專案文件描述為本機瀏覽器狀態 | 可能反映個別學生的學習表現；應限於必要用途，避免與身分資訊合併或外傳。 |
| 讀音覆寫紀錄 | 文件記載可包含字、修改後注音、備註、時間、年級、版本與課次；另記載有輔助欄位 `dict` | 使用者自行修改讀音；用於個人化顯示、匯出及可選擇回報 | `localStorage` 鍵名記載為 `zizai:readingOverrides:v1`；可複製文字或下載 JSON | 備註為使用者輸入的自由文字，即使有長度限制也可能包含姓名、聯絡方式或其他個人內容。介面應提醒不要填入身分、聯絡資訊或非必要內容。 |
| 回報資料 | 專案紀錄列出 `app`、`kind`、`message`、`ref`、`page`、`viewport`、`website` 等欄位；讀音修改的回報可能涉及字、注音、備註及教材脈絡 | 文件稱只有使用者勾選回報才送出；用途為維護者接收讀音回報 | 同源相對路徑 `POST /api/report`；服務端不在本 repo。專案紀錄稱限制特定網站來源及本機開發來源 | 實際 payload、API 接收者、必要性、IP／User-Agent 等請求中繼資料、服務端存取權、保存期限及刪除方式都須由 API 維護者確認。`message` 等欄位不得假定沒有個資。 |
| 瀏覽器／網路請求中繼資料 | IP 位址、User-Agent、來源頁面、請求時間等可能由外部服務或主機記錄；是否記錄與實際欄位未確認 | 載入網站、字型、外部連結或使用回報功能時可能產生 | Google Fonts、靜態主機、外部教育資源或回報服務依其實際設置處理 | 不屬於本 repo 可確認的資料庫欄位；須向服務營運者確認記錄種類、用途、所在地、保存期與刪除方式。 |
| 匯出檔案 | 讀音覆寫的文字或 JSON | 使用者主動匯出，供本人保存或交給他人 | 複製到剪貼簿或下載至使用者裝置；專案文件稱 JSON 不上傳 | 專案無法控制下載後的複製、轉傳、備份或刪除。匯出內容可能含備註及教材脈絡，需於匯出前提醒。 |
| 姓名／日期欄 | 考卷可顯示姓名、日期與得分欄 | 使用者在列印紙本自行填寫；未見網頁蒐集欄位的證據 | 紙本或使用者自行保存的輸出 | 不應把紙本欄位視為網站已蒐集；仍應避免要求使用者回傳含姓名或成績的考卷。 |

## 主要資料流

```text
使用者操作
  ├─ 學習進度、精熟狀態、讀音覆寫
  │    └─ 使用者瀏覽器 localStorage（文件記載）
  ├─ 讀音覆寫匯出
  │    ├─ 使用者剪貼簿
  │    └─ 使用者裝置的下載檔案
  └─ 使用者明確勾選讀音回報
       └─ 同源 POST /api/report
            └─ 外部整合站 API（不在本 repo；保存及刪除方式未知）

網頁載入
  ├─ 靜態主機提供 HTML、CSS、JavaScript、教材 JSON
  ├─ 網頁版向 Google Fonts 請求字型（文件／index.html 記載）
  └─ 使用者點擊外部教育資源連結後，瀏覽器前往目標網站

單檔離線版
  └─ 課程資料與前端資源內嵌於單一 HTML；文件稱移除 Google Fonts 請求
```

## 保存與刪除盤點

| 項目 | 可見機制 | 尚待確認／建議 |
|---|---|---|
| localStorage 學習狀態 | 文件稱存在使用者自己的瀏覽器；未提供明確保存期限 | 查完整程式碼確認所有 key、資料欄位、是否有總清除功能及遷移後舊 key 的處理。提供易懂的清除步驟；不要要求使用者寄送完整 localStorage 內容。 |
| 單筆讀音覆寫 | 文件記載有「還原」單筆修改或恢復辭典讀音的功能 | 確認還原是否確實刪除該筆紀錄，而非只改顯示；確認對匯出列與回報草稿的影響。 |
| 整體本機資料 | 文件未明確記載全體資料清除或到期機制 | 建議提供清除全部本機資料的明確入口，並說明清除瀏覽器網站資料亦可刪除，但會影響同來源其他網站資料的可能性。 |
| 匯出副本 | 使用者可複製或下載，專案不控制檔案後續去向 | 在匯出前提示內容可能含使用者備註及學習脈絡；提供檔案由使用者自行管理與刪除的說明。 |
| 回報 API | API 不在 repo，保存期限與刪除程序未知 | API 營運者須訂明用途、存取權、保留期間、刪除流程及聯絡窗口；確認使用者行使權利時如何轉介及處理。 |
| 靜態主機／第三方服務記錄 | 本 repo 無法確認平台日誌設定 | 向主機與外部服務營運者確認請求日誌欄位、保存期間、權限、備份及刪除政策。 |

## 可能的記錄檔／主控台外洩欄位

### 應優先檢查的欄位

- **使用者自由文字備註**：回報功能的 `message` 或同類欄位可能包含備註。若前端、API、反向代理或錯誤追蹤記錄完整 request body，可能保存使用者輸入。
- **讀音覆寫與教材脈絡**：字、注音、年級、版本、課次等欄位可顯示個人使用狀況；回報 payload 或除錯輸出若包含它們，須確認必要性。
- **請求中繼資料**：主機或第三方可能記錄 IP、User-Agent、來源頁面、時間及請求路徑；本 repo 未提供相應設定或記錄政策。
- **例外物件與 request body**：完整錯誤物件有機會帶出 URL、狀態、輸入資料或環境資訊。除錯時不應直接記錄整個 request、localStorage、表單或例外物件。
- **PDF 工具輸出**：`tools/make_sample_pdfs.mjs` 文件記載會輸出抽到的第一題句子。現有文件指出該工具使用範例教材，但它仍是內容輸出；勿將使用者自訂內容或個人資料帶入樣本生成與 CI 日誌。

### 建議日誌規則

1. 預設不記錄讀音備註、localStorage 全文、表單內容、回報 request body、匯出 JSON 或姓名／成績欄位。
2. 若回報 API 需要除錯，僅記錄必要的時間、處理結果、非內容識別碼及錯誤類別；對可能的識別碼採遮蔽或去識別化，並設保存期限及權限。
3. 使用受限權限及經遮蔽的測試資料檢視日誌；不得把真實使用者內容貼到 Issue、PR、測試輸出或一般除錯工具。
4. 由 API 與主機維護者確認日誌、備份、錯誤追蹤服務及第三方監控均採用相同的資料最小化與刪除規則。
