## F-01 CDP 呼叫沒有逾時，清理會一起卡住

- 優先級：P0
- 信心：已確認
- 位置：`tools/make_sample_pdfs.mjs` 的 `connect`，以及 `cleanup` 裡的 `cdp.send('Browser.close')`。同一條等待鏈還包含 `document.fonts.ready` 與 `Page.printToPDF`。
- 影響：`send` 把 Promise 放進 `pending`，連線中斷後沒有 `onclose` 拒絕這些 Promise，也沒有呼叫逾時。`cleanup` 先 `await` `Browser.close`，之後才有 3 秒的行程結束競賽與 `SIGKILL`。`Browser.close` 本身若永不返回，殺行程、關暫存伺服器、刪設定檔都不會發生。本機工具會留下無頭 Chrome 與暫存設定檔。
- 建議修法：
  1. 每個 CDP 呼叫包一層逾時：連線 10 秒、一般指令 30 秒、`Page.printToPDF` 60 秒、`document.fonts.ready` 5 秒。字型逾時後繼續印，離線包本來就用系統字型。
  2. `ws.onclose` 與連線錯誤要拒絕並清空 `pending`。`onerror` 在連線成功之後不能只拿來拒絕已經結束的連線 Promise。
  3. `Browser.close` 使用同一逾時。逾時或失敗後仍要執行現有的行程群組 `SIGKILL`、`server.close` 與刪除設定檔。
  4. `cleanup` 要共用同一個進行中的 Promise，避免訊號處理與 `finally` 各跑一次，後者還在第一次完成前就結束行程。
- 驗證方式：用會監聽埠但永不回應 CDP 的假行程取代 Chrome，工作目錄只用測試提供的暫存目錄。斷言行程在逾時後結束、假行程子行程不存在、暫存設定檔已刪。不要啟動系統上的 Chrome，不要連外網。再測一個會接受連線但 `Browser.close` 不回的假伺服器，確認 `SIGKILL` 仍會執行。

## F-02 中斷訊號沒有清理

- 優先級：P0
- 信心：已確認
- 位置：`tools/make_sample_pdfs.mjs` 的 `main`。只有 `finally` 會呼叫 `cleanup`。`spawn` 使用 `detached: true`，終止依賴負的 pid 行程群組。
- 影響：使用者中斷或外層逾時殺掉 Node 時，預設路徑不會跑到 `cleanup`。無頭 Chrome 與 `mkdtempSync` 的設定檔會留下。`chrome.pid` 在 spawn 失敗時可能還沒有可用值；對 pid 做負號前要確認它是正整數，避免訊號送錯對象。
- 建議修法：註冊 `SIGINT` 與 `SIGTERM`，呼叫同一個 `cleanup` Promise，完成後再結束行程。pid 不是正整數時跳過 `process.kill`。不要在清理函式裡再註冊新的訊號處理。
- 驗證方式：假 Chrome 啟動後對父行程送 `SIGINT`。斷言子行程已結束、暫存目錄已刪、行程結束碼不是成功。全程使用測試暫存目錄，不連外網。

## F-03 重建二年級資料會直接覆寫已發布 JSON

- 優先級：P0
- 信心：已確認
- 位置：`tools/build_datasets.py` 寫入 `data/curriculum-115-1.json`、`data/curriculum-110.json`、`data/curriculum-demo.json` 的三段 `json.dump`。解析在 `require_input`、`const DATA = ...` 的正則，以及 `js_obj_to_json`。
- 影響：寫入目標就是倉庫裡的教材檔，不是暫存檔。行程在 `json.dump` 中途結束會留下截斷 JSON，網頁版 `fetch` 後會解析失敗。三個檔依序寫入，後面一個失敗時前面的已經被替換。`js_obj_to_json` 用正則把 JavaScript 物件改成 JSON，來源形狀一變就可能寫出語意錯誤但仍然合法的 JSON。腳本在匯入時就會執行寫入，沒有主程式保護。
- 建議修法：
  1. 三份資料先在記憶體組完。驗證失敗就不要動舊檔。最低驗證：能被 JSON 解析、必要鍵存在、課次陣列長度大於 0、生字 `char` 為單一字。不要為了通過驗證而放寬既有 `data/schema.json`。
  2. 通過後寫到同一目錄的暫存檔，再以同檔系統的取代操作換上。三個檔都成功才算完成；任一取代失敗要在訊息裡列出已換上與未換上的檔名，不要自動刪舊檔。
  3. 主流程放進 `main`，只有直接執行時才寫檔。
  4. 讀取環境變數指向的輸入前先拒絕過大檔案（建議上限 32MB，超過就結束）。不要把輸入內容印出來。
- 驗證方式：在測試暫存目錄準備極小的假輸入，把輸出目錄指到暫存路徑，不要寫倉庫的 `data/`。案例要包含：寫入中途丟出例外後原檔位元組不變、第二個輸出驗證失敗時第一個原檔也不變、正則無法解析時結束碼非 0。假輸入裡的路徑與字串用明顯的測試值，不要使用真實憑證格式。

## F-05 啟動時剖析用不到的教材

- 優先級：P1
- 信心：已確認
- 位置：`tools/bundle.py` 的 `window.__EMBEDDED_GRADES__`、`window.__EMBEDDED_CURRICULUM_110__`、`window.__EMBEDDED_CURRICULUM_DEMO__`。被替換掉的來源註解寫明：先載目前年級的 115-1，以及 110 與體驗版，後兩者僅二年級用。
- 影響：單檔版把全部年級做成立即執行的物件字面量，HTML 解析之後 JavaScript 引擎就建立全部物件，即使用戶停在一個年級。110 與體驗版在一年級到六年級的預設路徑都會被載入，但介面只在二年級使用它們。網頁版若依同一註解實作，會多兩次 JSON 下載與剖析。記憶體仍要保留字串；能省的是啟動當下的剖析與用不到的網路。
- 建議修法：
  1. 內嵌資料改放 `type="application/json"` 的腳本區塊，或先以字串保存，第一次進入該年級或該教材類型才 `JSON.parse`，並沿用現有的年級快取。
  2. 110 與體驗版延到使用者選到該類型且年級是二年級再載入。選單切換當下會多一次等待，需要在介面保留現有的載入失敗提示。
  3. 不要改回「一次 fetch 全部年級」。版控裡的 JSON 維持可讀縮排，方便審閱；若要縮小傳輸，只壓縮發布副本或單檔內嵌。
- 驗證方式：在暫存目錄產一個只含少數假課次的單檔，用 Node 的 `vm` 或測試用 DOM 載入。斷言啟動後只有預設年級被剖析，切到另一個年級才剖析對應區塊，切到 110 之前不剖析 110。比較剖析前後的呼叫次數即可，不必量正式教材檔。

## F-07 範例 PDF 工具的其餘可靠性缺口

- 優先級：P1
- 信心：已確認
- 位置：`tools/make_sample_pdfs.mjs` 的 Chrome stderr 處理、`startServer`、`Page.navigate` 之後的輪詢。
- 影響：
  1. 取得 DevTools 位址後，stderr 的 `data` 監聽仍把輸出累加到同一個字串，長時間或高輸出時記憶體持續成長，每次還對整個緩衝做搜尋。
  2. `server.listen` 沒有錯誤處理。聽埠失敗時，回傳用的 Promise 不會完成，也不會進入 `cleanup`。
  3. 請求回呼裡的 `decodeURIComponent` 與 `new URL` 若丟出例外，例外發生在 `main` 的 `try` 外面，行程可能直接結束並跳過清理。
  4. `Page.navigate` 的結果沒有檢查失敗文字。頁面 404 或被拒時，仍每 200 毫秒輪詢到 20 秒才失敗。
  5. 路徑使用 `startsWith(ROOT)`。在「倉庫路徑剛好是另一個路徑的前綴」時可能誤放行。現有 URL 正規化已經擋下多數 `..`，這是縱深防禦，不是已示範的突破。
- 建議修法：
  1. 找到 DevTools 位址後移除 stderr 監聽，或改成固定上限的環形緩衝（建議 64KB），只在失敗時印出尾端。不要印頁面內文。
  2. `listen` 的 `error` 要拒絕 Promise。請求回呼整個放在 `try/catch`，畸形路徑回 400。
  3. 導覽結果帶失敗文字就立刻失敗。輪詢維持 20 秒上限。
  4. 路徑改用相對路徑計算，拒絕跳出倉庫根目錄的結果，並確認目標是檔案。
  5. Chrome 啟動失敗最多再試 1 次。`printToPDF` 失敗不要重試，避免兩份 PDF 來自不同次出題。
- 驗證方式：假 HTTP 與假 Chrome 都綁在測試暫存邏輯上，不聽外網介面。分別送出無法解碼的路徑、導覽失敗、stderr 大量輸出。斷言行程會結束、記憶體用的緩衝有上限、沒有殘留子行程。路徑案例只比較判斷結果，不讀取倉庫外的真實檔案。

## F-10 讀音回報的逾時與紀錄

- 優先級：P1
- 信心：待驗證。行為來自 `DONE_1151001.md` 第七輪的描述，不是 `src/readings.js` 原文。
- 影響：文件記載同源 POST、逾時 10 秒，404、403、429、斷線與逾時都降級，本機修改仍在。若成功返回後沒有清掉逾時計時器，計時器仍可能在 10 秒後 abort 已結束的請求，或留下未回收的計時器。自動重試會把同一則回報送出多次。
- 建議修法：對原文核對三件事：成功、失敗、逾時三條路徑都會 `clearTimeout` 並 `abort`；沒有重試迴圈；降級文案維持現況。除錯紀錄只留狀態碼、耗時與是否逾時，不留備註、訊息內文或讀音覆寫內容。預設不開這個紀錄。
- 驗證方式：沿用現有純函式測試的做法，注入會延遲的假 `fetch`。使用 `"FAKE_VALUE_FOR_TEST"` 當訊息欄位。斷言逾時只發生一次、成功後不會再 abort、呼叫次數為 1。不要對正式網域送出請求。

## F-12 注音字格的 DOM 與句子比對

- 優先級：P2
- 信心：已確認元件；主畫面是否整格重繪要看 `src/app.js`（待驗證）
- 位置：`src/zhuyin.js` 的 `makeGrid`、`cell`、`sentence`。

## F-13 單檔打包的寫入不是原子的

- 優先級：P2
- 信心：已確認
- 位置：`tools/bundle.py` 結尾對 `dist/index.html` 與 `dist/zi-zai.html` 的寫入。`ZIZAI_OUT` 可改輸出目錄。
- 影響：行程在寫入中途停止時，輸出檔是半套 HTML，雙擊開啟會得到解析失敗的頁面。兩個檔依序寫，只有第一個寫完時內容會不一致。`dist/` 可以重跑打包恢復，所以低於 F-03。

- 驗證方式：把 `ZIZAI_OUT` 指到測試暫存目錄，在寫入函式注入一次失敗。斷言沒有半套的目標檔名，或舊的完整檔仍可讀。不要寫倉庫的 `dist/`。

## F-14 失敗時看不出是哪一段慢、哪一類錯

- 優先級：P2
- 信心：已確認工具輸出；瀏覽器主程式的紀錄點要待 `app.js` 與 `readings.js` 原文
- 位置：`tools/bundle.py` 的 `fail` 與完成訊息、`tools/build_datasets.py` 的成功訊息、`tools/make_sample_pdfs.mjs` 的 `console.error`、單檔初始化的 `alert`。`DONE_1151001.md` 寫明回報失敗不寫主控台錯誤。
- 影響：PDF 工具掛住時看不出停在等 Chrome、等導覽、等字型還是等列印。重建腳本成功訊息沒有課次數與輸出位元組，無法和上一次比較。回報為了不干擾使用者而完全無聲，事後無法區分逾時、404 與離線。若把回報本文寫進紀錄，會把使用者備註留在主控台，這不該做。
- 建議修法：
  1. 工具用標準錯誤輸出階段名稱與耗時：`chrome.ready`、`page.ready`、`pdf.written`、`dataset.validated`。失敗再附上錯誤類別。
  2. 瀏覽器只在本機明示開啟除錯時，於記憶體留最後數筆 `{event, grade, status, elapsedMs}`。禁止欄位：讀音備註、回報訊息、localStorage 全文、課文句子。
  3. 回報失敗的使用者文案維持文件現況，不改成彈出主控台錯誤。
- 驗證方式：假失敗路徑斷言輸出含階段名稱、不含 `"FAKE_VALUE_FOR_TEST"` 以外的測試訊息全文。預設除錯關閉時，回報失敗的紀錄筆數為 0。

## F-15 多分頁寫入讀音覆寫可能互相覆蓋

- 優先級：P2
- 信心：待驗證
- 位置：`DONE_1151001.md` 記載鍵名 `zizai:readingOverrides:v1`，讀寫有 `try/catch`。`src/readings.js` 原文未提供，無法確認有沒有 `storage` 事件或版本合併。
- 影響：兩個分頁同時修改不同的字時，後寫入的整包 JSON 會蓋掉先寫入的另一包。這是可靠性問題，不是容量問題。單一瀏覽器的覆寫量大約是生字數等級，不會因這個鍵把 localStorage 寫到需要淘汰的程度。

## 建議的逾時與重試界線

| 操作 | 上限 | 重試 | 理由 |
|---|---|---|---|
| 網頁版年級 JSON | 15 秒，切換時取消 | 僅網路失敗與 502／503／504，最多 2 次 | 讀取是冪等的 |
| 讀音回報 POST | 維持文件的 10 秒 | 不重試 | 避免同一則回報送出多次 |
| CDP 連線 | 10 秒 | Chrome 啟動最多 1 次 | 只覆蓋暫時啟動失敗 |
| CDP 一般指令 | 30 秒 | 不重試 | 失敗就清理 |
| `Page.printToPDF` | 60 秒 | 不重試 | 避免兩份 PDF 不是同一次出題 |
| `document.fonts.ready` | 5 秒後繼續 | 不重試 | 系統字型可接受 |
| 考卷 DOM 輪詢 | 維持 20 秒 | 不重試 | 已有上限，需加上導覽失敗即停 |
| 教材重建寫檔 | 不另加網路逾時 | 不重試寫入 | 驗證失敗必須留下舊檔 |
