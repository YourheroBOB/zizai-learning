# 04 常見故障：症狀 → 診斷 → 處置

> 通則：先確認「是本機環境、資料、程式、還是外部相依」。能在本機重現的，一律先在本機修；不要直接改線上檔案。
> 本專案沒有後端，所以「伺服器 500」這類情況通常來自主機平台，不在本 repo 範圍。

## T1 雙擊 `index.html` 畫面空白或「教材資料載入失敗」

- **症狀**：網址列是 `file:///.../index.html`，畫面卡在載入或跳提示。
- **診斷**：網頁版以 `fetch` 讀 `data/*.json`，`file://` 被瀏覽器安全策略阻擋；Console 會有 fetch/CORS 相關錯誤。
- **處置**：改用 HTTP 伺服器（見 01 章第 3 節）；或改用已打包的單檔離線版 `dist/zi-zai.html`。
- **驗收**：`http://127.0.0.1:8000/` 可正常載入字卡。

---

## T2 部署後首頁或 `data/*.json` 回 404

- **症狀**：首頁白畫面，Network 面板有一或多個 404；或首頁正常但切年級失敗。
- **診斷**：
  1. 靜態主機的站台根目錄是否為 **repo 根目錄**（`index.html`、`src/`、`data/` 同層）。
  2. `.nojekyll` 是否還在（曾被 Jekyll 處理的站台會擋掉部分路徑）。
  3. 檔名大小寫與實際檔名是否一致（`curriculum-115-1-g3.json` 之類）。
  4. 是否只上傳了 `index.html` 而漏了 `src/` 或 `data/`。
- **處置**：補齊檔案結構後重新部署；不要用改名或改程式繞過。
- **驗收**：03 章 L0 全部 200。

---

## T3 切年級沒反應，Console 出現「年級 N 內嵌資料缺失」

- **症狀**：只有 `dist/` 版會出現；原始碼版（HTTP 伺服器）正常。
- **診斷**：打包時內嵌資料不完整，或 `GRADE_DATA_FILES` 改了但沒重新打包。
- **處置**：回原始碼確認 `data/` 五個年級檔存在 → 重新 `python3 tools/bundle.py` → 重新驗收離線版。
- **驗收**：Console 檢查 `window.__EMBEDDED_GRADES__` 含 1～6；每個年級都能出字卡。

---

## T4 `tools/bundle.py` 打包失敗

- **症狀**：腳本以「打包失敗：…」結束，未產生新檔。
- **診斷**：腳本對「每一處替換恰好命中一次」與「內聯 JS 的網路面」都有斷言。依訊息分類：

| 訊息類型 | 常見原因 |
|---|---|
| Google Fonts（preconnect／stylesheet）命中次數異常 | `index.html` 的 `<head>` 被改動（多一行、少一行、格式不同） |
| `loadGradeData` / init 載入 的起訖標記異常 | `src/app.js` 內對應函式被改名或搬動 |
| `app.js` 仍有 `fetch(` | 新增了網路請求（本專案設計上只允許一處、且需使用者勾選才送） |
| `fetchImpl(REPORT_PATH, init)` 或 `REPORT_PATH` 次數異常 | `src/readings.js` 的回報邏輯被改動 |
| 內聯 JS 出現 `XMLHttpRequest` / `sendBeacon` / `WebSocket` / `EventSource` / `importScripts` | 引入了不被允許的網路 API |
| 未列入白名單的外部網址 | 程式碼或字串裡出現新的外部 URL（白名單僅三個教育部連結與 SVG 命名空間） |
| `GRADE_DATA_FILES` 解析異常 | 年級對應表的寫法改變，腳本解析不到 |
| CSS／script 連結順序與預期不同 | `index.html` 的 `<link>`／`<script>` 順序被調整 |
| 殘留 `src/` 相對參照或外部資源 | 打包後仍有未內聯的參照 |

- **處置**：修**原始碼或腳本**使其符合設計，再重跑；**不要手改 `dist/` 產物**，也不要放寬斷言來讓打包過關。若確實需要新增網路能力，屬設計變更，需 BOB 決策。
- **驗收**：打包成功，且 `file://` 開啟後 Network 面板無外部請求。

---

## T5 `build_grades_from_sources.py` 直接結束（結束碼 2）

- **症狀**：印出取得方式後結束，`data/` 沒有任何變動。
- **診斷**：缺少 `data/sources/gsyan/` 的 CSV 快照或 `data/sources/moedict/` 的辭典檔。
- **處置**：依 `data/SOURCES.md` 取得（含 15 個分頁的檔名與 gid），放入對應資料夾後重跑。**不要**把來源檔提交進 repo。
- **驗收**：重跑後 `git diff --stat data/` 只有預期的年級檔變動；測試全過。

---

## T6 `build_datasets.py` 說找不到輸入

- **症狀**：明確說明缺少輸入並結束。
- **診斷**：二年級／110／體驗版的原始輸入不在 repo，需以環境變數指定（名稱見 02 章第 1 節）。
- **處置**：**先問「這次真的需要重建嗎」**。這三個資料集一般不需要重跑；真要重建才設定變數。沒有來源檔案就不要重建（不要手改 JSON 充數）。
- **驗收**：重建後 `git diff` 只有預期變動，測試全過。

---

## T7 測試有失敗，或大量項目「略過」

- **症狀**：`node tests/test_zizai.js` 出現 FAIL，或 21 項 SKIP。
- **診斷**：
  - 21 項略過＝環境不完整（無 CSV 快照 16 項、無辭典 4 項、無開發分支歷史 1 項）→ **正常**，不算失敗。
  - 有 FAIL＝資料或邏輯問題。
- **處置**：
  1. 資料類 FAIL：資料檔可能被手改 → 用重建腳本重跑，或從 git 取回原版。
  2. 邏輯類 FAIL（讀音標注、注音格式、語詞替換、回報 payload）：屬程式缺陷，開 PR 修。
  3. **不要**修改測試 expectation 來讓它變綠。
- **驗收**：87 通過 0 失敗（或 66 通過 21 略過）。

---

## T8 破音標記數量或讀音看起來不對

- **症狀**：某課標記比預期多／少；老師反映讀音與課本不同。
- **診斷**：
  1. 標記規則：`ambiguous`（最常見完整讀音占比 <85%）標強調「破音」；次要讀音占比 ≥10% 標一般「破音」；<10% 不標。
  2. 讀音採辭典詞頻法（含聲調），**不是逐課對照課本**，因此與課本不同是已知限制。
  3. 數量基準：全站標記 178 字（`ambiguous` 143）；清單見 `data/GAPS.md`，統計見 `GRADES.md`。
- **處置**：先確認是「規則問題」還是「個別字老師有疑義」。個別字疑義應引導使用者用「修改讀音」自行覆寫並匯出／回報，不要直接改資料檔。
- **驗收**：標記數與 `GAPS.md` 一致；測試通過。

---

## T9 修改讀音沒生效

- **症狀**：改了讀音但某處仍顯示舊的。
- **診斷**：
  - 字卡、詳情彈窗、線上練習：立即生效。
  - **A4 測驗卷：每次開新分頁會重新出題**，必須開新分頁才會套用。
  - 換裝置／換瀏覽器／無痕：修改不存在（只在本機）。
  - 清除瀏覽器資料：修改消失。
- **處置**：先用「匯出我的修改」確認資料存在，再針對情境說明；不要代為蒐集使用者修改內容。
- **驗收**：重新整理後仍在；開新分頁的考卷顯示新讀音；「還原」回到辭典讀音。

---

## T10 回報送不出去

- **症狀**：勾選「回報」後顯示「已存在你的瀏覽器；這個頁面無法送出回報」。
- **診斷**（依序）：
  1. 是否在使用白名單網域（非白名單環境一律不送，含 GitHub Pages、`file://`）。
  2. Network 面板的 POST 狀態碼：404／403／429／4xx／5xx 都會被降級處理（不跳 alert、不寫主控台錯誤）。
  3. 是否為逾時或離線。
- **處置**：前端行為是**刻意降級**，不是 bug。若是白名單網域仍持續失敗，整理「時間、狀態碼、頁面、重現步驟」通報整合站維護者（端點不在本 repo）。
- **驗收**：白名單環境成功時顯示「已回報，謝謝」；非白名單環境安靜降級。

---

## T11 A4 列印多一張空白頁或版面位移

- **症狀**：列印出來多一頁空白，或紙張內容往下掉。
- **診斷**：外層主容器在列印時仍有內距／寬度限制，導致 210mm×297mm 的紙張擠不進版心。`src/print.css` 已針對列印把主容器內距與最大寬度歸零（選擇器具體度足以壓過 `index.html` 內嵌樣式）。
- **處置**：確認 `src/print.css` 未被改動、`index.html` 的列印樣式沒有新增更高權重規則；用列印預覽（A4、邊界無）確認頁數。
- **驗收**：學生卷 1 頁＋答案卷 1 頁，共 2 頁，無空白頁。

---

## T12 手機 375px 出現水平捲軸

- **症狀**：小螢幕可左右滑。
- **診斷**：通常是新加的按鈕／標籤為 `white-space: nowrap` 且容器沒有 `min-width:0`／`max-width:100%`。
- **處置**：在對應容器補上寬度約束；沿用既有 `zz-` 前綴與語意權杖撰寫樣式。
- **驗收**：320 與 375 寬的 `scrollWidth` 不超過視窗寬。

---

## T13 字型沒載入、外觀與平常不同

- **症狀**：字型變成系統預設。
- **診斷**：網頁版向 Google Fonts 取字型；載入失敗會退回系統字型。離線單檔版**本來就沒有** Google Fonts。
- **處置**：屬外觀問題，功能不受影響。若企業／校園網路長期封鎖，可考慮自架字型（屬功能變更，需 BOB 決策）。
- **驗收**：功能正常即可接受。

---

## T14 部署後仍是舊版

- **症狀**：已部署但畫面／資料沒變。
- **診斷**：CDN 或瀏覽器快取；或部署流程其實沒完成。
- **處置**：先確認部署紀錄成功 → 用無痕或加版本查詢字串重測 → 確認檔案內容確實更新（例如取 `data/` 某檔的雜湊比對）。
- **驗收**：無痕視窗看到新版內容。

---

## T15 資料檔被手改／JSON 損毀

- **症狀**：前端載入失敗；測試資料模組 FAIL。
- **診斷**：`git diff data/` 有非預期變動；或 JSON 尾端多逗號、編碼壞掉。
- **處置**：
  1. 用 03 章第 3 節的解析檢查找出壞檔。
  2. 從 git 取回原版（見 05 章 R1），或依 01 章第 4 節重建。
  3. **不要**用編輯器手動修資料內容（會破壞可重現性與授權聲明一致性）。
- **驗收**：解析檢查全 OK；測試全過。

---

## T16 localStorage 被瀏覽器封鎖

- **症狀**：無痕模式或隱私設定下，修改讀音無法保存。
- **診斷**：程式已對取得／設定／移除都做 try/catch；封鎖時會提示「重新整理後修改會消失」並請先匯出，不會當機。
- **處置**：說明限制並引導匯出；不要要求使用者關閉隱私設定或上傳資料。
- **驗收**：頁面不當機、提示正確、匯出可用。
