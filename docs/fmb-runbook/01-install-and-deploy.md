# 01 安裝與部署

本章涵蓋：前置需求 → 取得程式碼 → 本機啟動 → 資料重建 → 打包離線單檔 → 測試 → 部署 → 部署後檢查。

---

## 1. 前置需求

| 工具 | 版本 | 用途 | 必要性 |
|---|---|---|---|
| git | 任何近期版本 | 取得程式碼、回滾 | 必要 |
| Node.js | **22 以上** | 跑 `tests/test_zizai.js`、`tools/make_sample_pdfs.mjs`（只用內建模組，**不需 npm install**） | 必要 |
| Python | 3.x | `python3 -m http.server` 本機靜態伺服器、資料重建腳本 | 必要 |
| Chrome／Chromium | 近期版本 | 僅重產範例 PDF（`tools/make_sample_pdfs.mjs`） | 選用 |
| curl／jq | 任何近期版本 | 健康檢查 | 選用 |

- 專案**沒有** `package.json`、沒有建置相依套件、沒有後端服務，`npm install` 不需要也不應該執行。
- 不需要資料庫、不需要環境變數即可啟動網頁版。

---

## 2. 取得程式碼

```bash
git clone <REPO_URL> zizai-learning
cd zizai-learning
git switch <WORK_BRANCH>
git status --short
```

注意：

- 不要直接在預設分支上提交；先在專屬分支完成，再由 BOB 決定合併。
- **不要** `git push`、不要 merge、不要改 remote、不要刪分支（除非任務明確授權）。
- 確認 `git status --short` 乾淨再開始，避免把不相關變更帶進部署。

---

## 3. 本機啟動（網頁版）

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

瀏覽器開 `http://127.0.0.1:8000/`。

**為什麼不能雙擊 `index.html`**：網頁版用 `fetch` 讀 `data/*.json`，`file://` 會被瀏覽器擋下，畫面會停在載入失敗。單檔離線版（`dist/zi-zai.html`）才可以雙擊開。

本機驗收（每項都要看過）：

1. 年級下拉切一～六年級都能載入資料（切換時按需載入，不預載全部）。
2. 版本下拉切康軒／翰林／南一都正常；110 學年度與體驗版只有二年級，切其他年級會自動回首選的 115-1，**這是預期行為**。
3. 生字進度頁：字卡、破音標記、「家長自訂教學進度」覆寫可運作。
4. 線上練習頁：三種出題範圍（本週課次／已教累計／加強不熟）與題數都可抽題。
5. A4 測驗卷頁：可重新出題、可列印預覽、學生卷不洩答、答案卷另起一頁。
6. 開發者工具 Console **沒有**錯誤（Google Fonts 載入失敗只影響外觀，不算錯誤）。

## 4. 資料重建（通常不需要）

### 4.1 何時才需要

- 來源生字清單更新（換學期、出版社調整課次）。
- 讀音規則調整（例如辭典詞頻法或 `ambiguous` 門檻變更）。
- 需要重現 `data/curriculum-115-1-g*.json`（授權要求可重現）。

一般「改前端、改文案、改樣式」**不需要**重建資料。

### 4.2 需要的輸入（都不進版控）

| 輸入 | 放哪裡 | 取得方式 |
|---|---|---|
| 顏國雄老師試算表 15 個分頁的 CSV 快照 | `data/sources/gsyan/`（檔名與 gid 見 `data/SOURCES.md`） | 自行下載；`.gitignore` 已排除 |
| 教育部《重編國語辭典修訂本》開放資料 `dict-revised.json.xz` | `data/sources/moedict/`（腳本會自動解壓） | 自行下載；`.gitignore` 已排除 |

下載前先讀 `data/SOURCES.md` 的授權說明。**不要把這些檔案提交進 repo。**

### 4.3 執行

```bash
python3 tools/build_grades_from_sources.py
```

- 缺少任一 CSV 快照或辭典檔時，腳本會**印出取得方式後結束（結束碼 2）**，不會崩潰、不會改寫任何資料檔 → 照訊息補齊檔案再重跑。
- 成功後檢查差異：

```bash
git diff --stat data/
```

預期只會動到一、三、四、五、六年級五個資料檔（`data/curriculum-115-1-g*.json`）；若出現其他檔案變動，先停下確認原因。

### 4.4 二年級／110 學年度／體驗版

由 `tools/build_datasets.py` 產生，原始輸入**不在 repo**，需以環境變數指定（變數名稱見 02 章）。**一般情況不需要重跑**：二年級資料是建站時整理好的原始資料，維持相容性。缺輸入時腳本會明確說明並結束，不會產生半套資料。

### 4.5 重建後必做

1. 跑測試（第 7 節）。
2. 若有發布離線單檔，重新打包（第 5 節）。
3. 檢視 `git diff` 是否只有預期欄位變動（例如只動 `meta.licenseNotes`）。
4. 需要時同步更新 `data/GAPS.md`、`GRADES.md`、`README.md`（屬既有檔案，改動需在任務範圍內）。

## 5. 打包單檔離線版（選用）

**前置**：資料檔已是最新版本。

```bash
python3 tools/bundle.py
```

- 輸出：`dist/index.html` 與 `dist/zi-zai.html`（兩檔內容相同）。
- 可用環境變數改輸出資料夾（名稱見 02 章）。
- 打包腳本設計為**失敗即中止**：每一處文字替換都要求「恰好命中一次」，CSS／JS 連結順序、內聯 JS 的「網路面」白名單都會逐一斷言。任何錯誤訊息都代表原始碼與腳本假設不一致，**要修原始碼或腳本，不要手改產物**。
- 打包會做的事：移除 Google Fonts 三行、把資料載入改為讀內嵌資料、CSS/JS 內聯、一～六年級＋110＋體驗版資料內嵌。

驗收：

1. 直接雙擊 `dist/zi-zai.html`（`file://`）可正常開啟並切換年級。
2. 斷網後仍可開啟與操作。
3. 開發者工具 Network 面板應該**沒有**外部請求。
4. `dist/` 是否納入版控、放哪裡發布，目前未定 → 見文末「需 BOB 決策」。


- 找不到 Chrome 時，用環境變數指定路徑（名稱見 02 章）。
- 產出兩份：含答案版（學生卷＋答案卷，2 頁）與學生版（1 頁），**來自同一次出題**。
- 腳本會自己起一個只聽 127.0.0.1 的臨時靜態伺服器與無頭 Chrome，結束時自行清理；不會碰別人的 Chrome 行程。

## 7. 測試

```bash
node tests/test_zizai.js
```

期望值：

| 情境 | 結果 |
|---|---|
| 已補齊 CSV 快照與辭典檔 | 87 項通過、0 項失敗 |
| 單純 clone（沒有 `data/sources/`） | 66 項通過、21 項略過（**略過不算失敗**，含 16 項快照比對、4 項辭典、1 項開發分支歷史比對） |

判讀順序：

1. 先看**哪個模組**失敗（資料合規／注音一致性／破音標注／打包不相關）。
2. 資料類失敗幾乎都是「資料檔被手改」或「重建沒跑完」→ 用第 4 節重跑並比對 `git diff`。
3. 邏輯類失敗（讀音標注、注音格式、語詞替換、回報 payload）→ 屬程式缺陷，走 PR 修，不要改測試 expectation 掩蓋。

## 8. 部署：GitHub Pages（主要方式）

### 8.1 站台結構

- 站台根目錄＝**repo 根目錄**；`index.html`、`src/`、`data/` 必須同層可讀。
- `.nojekyll` 必須存在（避免 Jekyll 處理，並讓底線開頭的資源可被服務）。
- 網頁版**沒有建置步驟**：推送即為最終內容。

### 8.2 步驟

1. 確認變更已在分支上通過測試（第 7 節）與本機驗收（第 3 節）。
2. 由 BOB 合併到發布分支（維運端**不要**自行 merge 或 push）。
3. 等待平台完成部署（部署紀錄由平台提供）。
4. 依 03 章的 L0–L3 檢查驗證。
5. 在工單記錄：變更摘要、commit、部署時間、驗證結果。

### 8.3 禁止事項

- 不得修改 `.github/workflows`、secrets、憑證、環境設定。
- 不得為了「先上線」直接改線上檔案或手動覆蓋 `data/*.json`。

### 8.4 快取提醒

CDN 與瀏覽器可能暫存舊檔。驗證時用無痕視窗，或加上版本查詢字串；若「程式已更新但畫面沒變」，先排除快取再判斷為故障。

## 9. 部署：其他靜態主機／整合站

1. 需要的檔案：`index.html`、`src/`（5 個 CSS＋3 個 JS）、`data/`（9 個 JSON：`curriculum-110.json`、`curriculum-115-1.json`、`curriculum-115-1-g1/g3/g4/g5/g6.json`、`curriculum-demo.json`、`schema.json`）、`.nojekyll`（若主機不處理）。
2. 所有參照都是相對路徑，**可以放在子路徑**（例：`/zizai/`），但整個資料夾結構要一起上去。
3. 若只要單檔：上傳 `dist/zi-zai.html`（需先在本機打包）。
4. 回報功能走同源相對路徑；**非白名單網域不會送出**（前端會降級顯示一行說明），這是設計行為，不是故障。要開啟回報需整合站維護者調整伺服器端設定（不在本 repo）。
5. 整合站要注意路由不會碰撞，且不要覆蓋整合站既有的 worker。
