# 05 回滾程序

> 原則：**能安全回滾就先回滾，再排時間修**。回滾一律用「新增反向 commit」的方式，不改寫歷史、不 force push。
> 本專案是靜態站且無資料庫，回滾不會造成資料遷移問題；唯一要考慮的是**使用者瀏覽器內的資料**（進度、讀音修改）在不同版本間的相容性。

---

## 1. 先判斷：回滾還是修復？

| 情況 | 建議 |
|---|---|
| 首頁不可用、資料載入失敗、整站白畫面 | **立即回滾**（R2／R3） |
| 單一資料檔內容錯誤（例如某課生字錯） | 回滾該檔（R1） |
| 單一畫面退化（列印多一頁、破音標記錯位） | 可先修；若當日修不完則回滾（R2） |
| 外部相依異常（字型、教育部連結、回報端點） | **不回滾**，確認降級正常並通報對方 |
| 只有離線單檔產物異常 | 換回上一版產物（R4） |

---

## 2. 回滾分級

| 級別 | 範圍 | 影響 | 復原時間 |
|---|---|---|---|
| R1 | 單一資料檔 | 只影響該年級／課次 | 分鐘級 |
| R2 | 程式或樣式（一個 commit） | 全站 | 分鐘級（含平台部署等待） |
| R3 | 整站回到舊版本（標籤） | 全站，功能回溯 | 十分鐘級 |
| R4 | 離線單檔產物 | 只影響下載／單檔使用者 | 分鐘級 |

---

## 3. R1：回滾單一資料檔

適用：`data/curriculum-115-1-g*.json` 內容有誤、JSON 損毀。

```bash
# 1) 找到最後一個正確的 commit
git log --oneline -- data/curriculum-115-1-g3.json | head -n 5

# 2) 先看差異，確認只回滾預期內容
git diff <GOOD_SHA> -- data/curriculum-115-1-g3.json | head -n 80

# 3) 取回該版本
git checkout <GOOD_SHA> -- data/curriculum-115-1-g3.json

# 4) 驗證
node tests/test_zizai.js
git diff --stat
```

注意：

- 若該檔本來就是「由腳本產生」，正確做法是**修來源或腳本後重建**，而不是長期手動回滾檔案；R1 只當止血。
- 回滾後 `meta.licenseNotes` 等授權欄位要維持正確說法，不可為了回滾而放寬。

---

## 4. R2：回滾程式或樣式（反向 commit）

適用：`index.html`、`src/*`、`tools/*`、`tests/*` 的變更造成線上異常。

```bash
# 1) 找出問題 commit
git log --oneline -n 20

# 2) 產生反向 commit（不要 reset、不要 force push）
git revert --no-edit <BAD_SHA>

# 3) 驗證
node tests/test_zizai.js

# 4) 若有發布離線單檔，重新打包
python3 tools/bundle.py
```

- 多個 commit 一起出問題：`git revert --no-edit <OLDEST>^..<NEWEST>`（ revert 範圍），逐一確認衝突。
- 由 BOB 決定合併與部署；維運端不自行 push 或 merge。
- 部署後依 03 章 L0–L3 驗證，並確認無快取殘留（T14）。

---

## 5. R3：整站回到舊版本（標籤）

`README.md` 記載本次多年級擴充之前的版本保留在標籤 `pre-grades-1151001`（該版本只有二年級）。

**執行前必做**：

```bash
git tag -l 'pre-grades-*'        # 先確認標籤真的存在於此 clone
git show --stat pre-grades-1151001 | head -n 30
```

步驟：

1. 確認標籤存在且內容符合預期（該版本**沒有** `src/readings.js`、沒有多音字標注與修改讀音功能）。
2. 用 worktree 或臨時分支檢出該版本，先在本機起站驗證，**不要直接改動目前分支**：

```bash
git worktree add ../zizai-rollback pre-grades-1151001
cd ../zizai-rollback && python3 -m http.server 8001 --bind 127.0.0.1
```

3. 驗證通過後，由 BOB 決定以何種方式發布（例如以反向 commit 把目前分支內容退回該狀態，或由平台改指向該版本）。**不要**直接刪分支或改 remote。
4. 驗證與記錄。

**副作用提醒**：

- 舊版沒有讀音修改功能，使用者已存在的 `zizai:readingOverrides:v1` 資料不會被刪除，但舊版不會使用它；**不要**要求使用者清除。
- 舊版沒有進度鍵的新版結構；若新舊鍵名不同，使用者的進度顯示可能回到預設值。回滾說明要一併告知（不要代為清除資料）。

## 6. R4：回滾離線單檔產物

適用：`dist/zi-zai.html`、`dist/index.html` 發布後發現問題（例如內嵌資料不完整、外部請求殘留）。

1. 保留**上一版可用產物**（建議保存檔名含 commit 前綴與 md5）。
2. 回滾方式二選一：
   - 直接換回上一版產物（最快，但產物與原始碼可能不同步，需註記）。
   - 回到正確的原始碼 commit 後重新打包：

```bash
git checkout <GOOD_SHA> -- index.html src data
python3 tools/bundle.py
```

3. 驗收：`file://` 可開、斷網可用、Network 無外部請求、六個年級可切。

注意：`dist/` 是否納入版控目前未定（見 06 章「需 BOB 決策」）。若未納版控，**一定要自行保存上一版產物**，否則無法快速回滾。

- [ ] `node tests/test_zizai.js` 通過（87／0 或 66＋21 略過）

- [ ] 無痕視窗確認不是快取造成的假象
- [ ] 工單記錄：觸發原因、回滾級別、涉及的 commit／標籤、開始與結束時間、驗證結果
- [ ] 通知關係人（使用者可見的異常才需要對外說明）
- [ ] 開一張「根因與長期修正」的票，避免只止血不修因

---

## 8. 禁止事項

1. 不使用 `git reset --hard` 後 force push；不改寫已發布歷史。
2. 不改 git remote、不刪分支、不動 `.github/workflows` 與 secrets。
3. 不在線上直接編輯 `index.html` 或 `data/*.json` 當作回滾手段。
4. 不為了讓測試變綠而修改測試 expectation。
5. 不回滾「授權說明」到與來源事實不符的版本（授權欄位的正確性優先於功能回滾）。
