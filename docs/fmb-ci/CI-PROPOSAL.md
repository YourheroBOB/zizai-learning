# zizai-learning CI／品質關卡提案

> 本文件是 CI 設計提案，不代表目前已有對應的 GitHub Actions、掃描器或部署設定。本次只新增文件，不建立或修改 `.github/`、既有工作流程、secrets 或憑證設定。

## 1. 專案現況與設計原則

依目前提供的檔案清單，專案是以 HTML、CSS、JavaScript、JSON 和 Python 工具為主的靜態前端專案：

- 沒有 `package.json`、npm lockfile、Python 相依清單或 TypeScript 設定；應避免為了 CI 強行增加執行期相依。
- 主要邏輯與資料測試為 `node tests/test_zizai.js`；另有 Node.js 測試檔 `tests/test_fmb_zhuyin.test.mjs`。
- 單檔建置可用 `python3 tools/bundle.py`；此工具會輸出檔案，因此 CI 範本將產物放在工作目錄內的臨時資料夾並清理。
- `README.md` 說明，在沒有外部來源快照的全新 clone 中，部分快照比對會「略過」。CI 不應下載或提交這些來源檔，也不得把「略過」計成通過。
- `README.md` 記錄的測試基準是無快照情況下 66 項通過、21 項略過；這是文件所述基準，不是本次實際執行結果。

CI 工作應只對 repo 內容及公開套件登錄站執行所需檢查；不得呼叫正式服務、讀取使用者瀏覽器資料，或要求新增憑證。

## 2. 建議的關卡與初始政策

| 關卡 | 初始政策 | 檢查內容與注意事項 |
|---|---|---|
| Lint／靜態檢查 | 必要 | 對 JavaScript 執行語法檢查及少量、低風險的 lint 規則。Python 工具以標準函式庫解析語法。先避免引入未經基準驗證的大量風格規則。 |
| 型別 | 條件式 | 目前沒有 TypeScript 或 JS 型別檢查設定，狀態應明確標示為 N/A。將來加入 `tsconfig.json` 或 `jsconfig.json` 後才執行型別檢查；新增設定前先處理既有型別錯誤及全域符號宣告。 |
| 測試 | 必要 | 執行 `node tests/test_zizai.js` 與 `node --test tests/test_fmb_zhuyin.test.mjs`。失敗時阻擋合併。快照缺失造成的略過須在結果中維持可見，不得以假資料替代或當作通過。 |
| 覆蓋率 | 先報告、後設門檻 | 用 V8 覆蓋率工具產生 `src/` 的報告，先確認實際涵蓋範圍並建立基準。現有內容不足以推算可信的覆蓋率門檻；不要在未量測前以任意門檻阻擋合併。建立基準後再設最低門檻及逐步提升計畫。 |
| 相依掃描 | 有 lockfile／相依清單時必要 | 目前沒有套件清單或 lockfile，因此應明確報告 N/A，而不是執行 `npm install`。新增相依時一併提交 lockfile，並對其所屬生態系執行稽核；遇到未納入掃描器的相依格式時，應失敗並要求補上掃描支援。 |
| 秘密掃描 | 必要 | 對 PR 與 Git 歷史掃描，輸出必須遮罩命中值。不要把掃描結果中的敏感片段複製到 PR、artifact 或文件。若有命中，使用 repo 既有的秘密事件處理流程；不得在 CI 中自動重寫歷史或刪除分支。 |
| 建置 | 必要 | 執行資料不需外部來源的單檔建置，確認兩份輸出存在且相同。建置產物只在 CI 工作目錄內暫存；不提交、不發布，也不覆寫來源檔。 |
| 發佈 | 僅在所有必要關卡成功後 | 發佈不應由 PR 工作流程觸發。待 BOB 確認預設分支、GitHub Pages 現有發布來源與審核方式後，再決定發布工作流程及必要的平台設定。 |

## 3. 建議執行順序

1. **靜態檢查**：JavaScript lint、JS 語法與 Python 語法。
2. **型別檢查**：有型別設定才執行；現況明確標示 N/A。
3. **測試**：先跑專案既有測試，不補下載教材來源快照。
4. **覆蓋率**：產生報告；建立可信基準前不阻擋。
5. **相依掃描**：依 lockfile 與相依清單決定掃描器；現況標示 N/A。
6. **秘密掃描**：遮罩輸出並檢查 PR 變更與 Git 歷史。
7. **建置**：生成單檔並檢查輸出，不發布。
8. **發佈**：只允許在必要關卡全部成功後，由已確認的發布流程執行。

可直接採用的 CI 範本見 [WORKFLOW-TEMPLATE.md](WORKFLOW-TEMPLATE.md)。該範本只提供文件中的候選內容，不會建立工作流程檔。

## 4. 保護與維運建議

- 將 lint、測試、秘密掃描、建置與已啟用的相依掃描列為必要檢查；型別與覆蓋率在尚未啟用或仍建立基準時，不應偽裝成已通過。
- 對 CI 工作設定最小權限；驗證工作只需要讀取內容時，僅授予讀取權限。
- 第三方 Actions 與掃描器應固定到經審核的版本；要採用 commit SHA 固定時，先由維護者確認 SHA 與升級流程，不在提案中猜測 SHA。
- 套件掃描可能連到公開套件登錄站；該流量只用於相依弱點資料，不應連到正式服務。若 CI 執行環境不得外連，須改用維護者核准的內部鏡像或預先提供的掃描器。
- 目前沒有發布憑證需求可由本 repo 檔案證實。本提案不要求新增 secrets、憑證或外部服務帳號。
- 不要把教材原始快照、使用者匯出資料或任何未核准資料上傳為 CI artifact。
