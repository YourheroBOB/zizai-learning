# HTTP 端點：`POST /api/report`（前端回報讀音）

字在的前端在使用者**主動勾選**「同時回報給維護者」時，會以同源相對路徑 `POST /api/report` 送出一筆讀音修改回報。伺服器端由部署環境提供，**不在本 repo 內實作**；本文件描述前端送出的契約與可觀察到的伺服器行為。

## 端點

| 項目 | 內容 |
|---|---|
| 方法 | `POST` |
| 路徑 | `/api/report`（相對路徑，跟隨目前頁面的來源） |
| 內容型別 | JSON |
| 認證 | 無（同源請求） |
| 重試 | 無；失敗即降級 |

`tools/bundle.py` 會斷言：整份內聯 JS 中 `fetchImpl(` 呼叫恰好 1 處、`REPORT_PATH` 只定義一次且為 `/api/report`、`app.js` 交付 `window.fetch` 的位置恰好 1 處。新增任何其他網路寫入都會讓打包失敗。

## 請求內容

| 欄位 | 型別 | 說明 |
|---|---|---|
| `app` | `string` | 應用識別；字在使用 `zizai` |
| `kind` | `string` | 回報種類 |
| `message` | `string` | 回報內容（含使用者修改的讀音與其自行輸入的備註） |
| `ref` | `string` | 來源參照（頁面／單元等定位資訊） |
| `page` | `string` | 目前頁面路徑 |
| `viewport` | `string` | 目前視窗尺寸 |
| `website` | `string` | 蜜罐欄位，**必須是空字串**；非空視為機器人 |

範例（值為示意，實際內容由前端組出）：

```json
{
  "app": "zizai",
  "kind": "FAKE_KIND_FOR_TEST",
  "message": "FAKE_MESSAGE_FOR_TEST",
  "ref": "FAKE_REF_FOR_TEST",
  "page": "/",
  "viewport": "375x812",
  "website": ""
}
```

## 送出條件

只有在同時符合下列條件時才會送出：

1. 使用者在面板中勾選「同時回報給維護者」（預設**不勾**）。
2. 目前頁面來源在白名單內。

來源白名單（與部署端 worker 的 `isAllowedOrigin` 相同）：

| 來源 | 是否送出 |
|---|---|
| `https://toopower.cc` | 是 |
| `https://www.toopower.cc` | 是 |
| 本機開發主機（`http://localhost`、`http://127.0.0.1`） | 是（方便本機端到端驗證） |
| GitHub Pages、其他網域、`file://` | 否 |
| 單檔離線版以 `file://` 開啟 | 否 |

不在白名單時**完全不發出請求**；使用者的修改仍存在自己的瀏覽器，可用「匯出」自行帶走。

## 回應處理

| 情況 | 前端行為 |
|---|---|
| 成功（2xx） | 顯示「已回報，謝謝」 |
| 失敗（404、403、429、400、413、500、502 等非 2xx） | 降級為一行說明「已存在你的瀏覽器；這個頁面無法送出回報」 |
| 網路錯誤、離線、逾時（10 秒） | 同上降級 |
| 同步丟錯（例如 `fetch` 被封鎖） | 同上降級 |

降級時**不跳 `alert`、不寫主控台錯誤**；使用者的修改不受影響。

瀏覽器在真實伺服器回非 2xx 時可能自行在主控台記一行網路失敗訊息，那是瀏覽器行為，不是程式錯誤。

## 伺服器端（部署環境）可觀察行為

以下為測試觀察到的契約要點，實作不在本 repo：

- 需驗證 `app` 欄位值，部署版 worker 的應用識別規則必須接受 `zizai`；否則會回 `400`，錯誤指向 `app` 欄位。
- `website` 非空時應視為垃圾請求。
- 回應狀態碼會影響前端顯示（見上表），前端對任何非 2xx 一律降級，不會無限重試。

## 隱私與資料處理

- 回報內容含使用者自行輸入的備註與修改紀錄；維護者端不應公開張貼，並應依個資最小化原則處理（只保留除錯所需欄位）。
- 前端不會送出瀏覽器儲存的完整進度資料，只送本次回報所需欄位。
- 文件與測試不使用真實憑證或個人資料；假值一律使用 `FAKE_VALUE_FOR_TEST` 這類字串。
