# 字在系統操作手冊

## 1. 環境與安裝

本專案是靜態前端，不需安裝 npm 套件。網頁版需要 Python 3 或其他可提供靜態檔案的本機 HTTP 伺服器；自動化測試使用 Node.js 內建模組。產生範例 PDF 另需 Node.js 22 以上及 Chrome。

建議先確認：

```sh
python3 --version
node --version
```

執行測試與網頁版不需安裝 `node_modules`。

## 2. 執行網頁版

在倉庫根目錄啟動只綁定本機介面的伺服器：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

用瀏覽器開啟：

```text
http://127.0.0.1:8000/
```

網頁版會透過 HTTP `fetch` 讀取 `data/*.json`；不要以 `file://` 直接開啟根目錄 `index.html`，否則瀏覽器通常無法載入 JSON。Google Fonts 載入失敗時會使用系統字型，不影響主要功能。

## 3. 執行單元與資料測試

在倉庫根目錄執行：

```sh
node tests/test_zizai.js
```

測試使用 Node.js 內建模組，不需連線到正式服務，也不需安裝套件。測試涵蓋週次與進度、抽題、注音繪製邏輯、各年級資料格式、讀音標示與覆寫、資料一致性，以及相關介面邏輯。

### 如何解讀測試結果

- `tests/RESULT_1151001g.txt` 記錄一輪 87 項全部通過的結果；其他 `tests/RESULT_1151001*.txt` 是不同階段的歷史輸出，不一定對應目前程式。
- 依 `README.md` 說明，若沒有自行取得的辭典檔與來源 CSV 快照，部分依賴這些檔案的測試會標示「略過」。單純複製倉庫時，預期為 66 項通過、21 項略過；有齊測試所需來源檔時才可能執行完整比對。
- 「略過」不等於通過。檢查總結中的通過、失敗及略過數量；若有失敗，先依該項訊息確認是輸入資料缺失、格式問題或程式行為改變。
- 外部來源檔不是倉庫內的必要執行依賴；不要為了讓測試全數執行而提交來源檔或未確認授權的資料。

## 4. 產生單檔離線版

在倉庫根目錄執行：

```sh
python3 tools/bundle.py
```

預設輸出為 `dist/index.html` 與 `dist/zi-zai.html`。打包會將 CSS、JavaScript 與教材資料內嵌，移除 Google Fonts 資源，並檢查替換命中數、載入順序及程式中的網路呼叫。任一檢查不符合預期時，腳本會報錯停止。

可用環境變數 `ZIZAI_OUT` 指定輸出資料夾。打包頁面可直接以 `file://` 開啟；讀音修改仍屬瀏覽器本機資料，建議在清除瀏覽器資料前先匯出。

## 5. 重建教材資料

### 一、三至六年級

生成器為：

```sh
python3 tools/build_grades_from_sources.py
```

執行前需自行依 `README.md` 的「如何重建資料」及 `data/SOURCES.md` 取得所需 CSV 快照與教育部辭典資料，放到文件指定的 `data/sources/` 位置。來源快照不隨倉庫提供，取得及使用前須確認授權條件。

缺少必要來源檔時，生成器會說明缺少的輸入並以結束碼 2 結束，不應因此手動補造資料。執行前先確認輸入完整，並在執行後檢查產生檔及測試結果。

### 二年級、110 學年度與體驗版

`tools/build_datasets.py` 使用的原始輸入不在倉庫；依 `README.md`，需透過 `ZIZAI_G2_HTML` 與 `ZIZAI_KIMI_JS` 環境變數指定輸入。一般使用與執行測試不需要重跑此建置流程。不要在沒有來源及授權確認的情況下重建或散布資料。

## 6. 產生範例 PDF

先更新單檔離線版，再執行：

```sh
python3 tools/bundle.py
node tools/make_sample_pdfs.mjs
```

此工具需 Node.js 22 以上及 Chrome。若 Chrome 不在工具預設搜尋位置，可設定 `CHROME_BIN` 指向本機 Chrome 執行檔。預設 PDF 輸出至 `dist/`；產生程序使用本機暫時伺服器與專用瀏覽器設定檔，不會使用正式服務。

## 7. 除錯步驟

### 頁面空白或教材未載入

1. 確認伺服器是從倉庫根目錄啟動，瀏覽器網址使用 `http://127.0.0.1:8000/`。
2. 開啟瀏覽器開發者工具的 Network 面板，確認 `data/*.json` 請求成功，且回應為有效 JSON。
3. 若以 `file://` 開啟根目錄頁面，改用 HTTP 伺服器；只有已打包的離線 HTML 預期可直接以 `file://` 開啟。
4. 若只有外部字型載入失敗，先確認頁面可正常顯示；系統字型是預期備援。

### 測試失敗或出現略過

1. 執行 `node tests/test_zizai.js`，查看失敗項目及完整錯誤訊息。
2. 確認測試需要的教材 JSON 存在且可解析。
3. 若項目依賴來源 CSV 或辭典檔，依 `README.md` 與 `data/SOURCES.md` 確認本機輸入是否齊全；缺少輸入時略過是已知行為。
4. 對照 `tests/RESULT_1151001g.txt` 時，注意它是歷史測試輸出，不是本次執行的即時結果。

### 讀音修改、保存與回報

- 讀音修改預設保存在瀏覽器 `localStorage`，鍵名為 `zizai:readingOverrides:v1`。若瀏覽器停用或限制本機儲存，修改可能只在目前頁面暫存。
- 修改只影響該瀏覽器；換裝置或清除網站資料前，先使用介面提供的文字或 JSON 匯出功能。
- 回報只有在使用者主動勾選後才會嘗試送出，且需符合程式設定的來源條件。GitHub Pages、離線檔案及其他不符合條件的環境不會送出；送出失敗不應令本機修改失效。
- 此倉庫沒有 `/api/report` 的伺服器端程式。若部署頁面回報失敗，應先確認部署環境是否提供相符的同源端點；不要以正式服務作為本機測試依賴。

### 打包失敗

1. 查看終端機輸出的「打包失敗」訊息，找出資源順序、替換標記、資料檔或網路檢查哪一項不符。
2. 確認 `index.html`、`src/` 與 `data/` 檔案內容一致且必要檔案存在。
3. 不要略過或移除打包檢查來掩蓋問題；修正後重新執行 `python3 tools/bundle.py`。

## 8. 安全與資料注意事項

- 本操作手冊不要求提供或設定任何憑證。
- 不要把來源 CSV、辭典原檔、使用者讀音匯出檔或瀏覽器本機資料提交到倉庫。
- 教材來源及授權資訊以 `README.md`、`data/SOURCES.md`、`data/GAPS.md` 為準；重建或發布前先確認相關條件。
- 測試與本機除錯使用本機檔案及本機伺服器即可，不需連線到網路上的正式服務。
